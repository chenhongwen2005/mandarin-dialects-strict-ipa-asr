На базе кодировщика [SenseVoiceSmall](https://github.com/FunAudioLLM/SenseVoice), поверх которого установлена **голова декодирования CTC в узкой IPA**; с помощью полной тонкой настройки (full fine-tuning) выполняется транскрипция путунхуа на уровне «слог + тон».

Модель выводит последовательность узких IPA-слогов, разделённых пробелами, каждый слог несёт собственный символ тонального значения (напр. `ɡ̊wa̠n̚˥`, `x̞wa̠ɪ̯˧˥`) — то есть одновременно даёт инициаль/финаль и тон, что подходит для фонетического анализа, оценки произношения путунхуа, обучения тонам и т.п.

> Лицензия: **CC BY-NC-SA 4.0** (Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International).
> Веса модели и обучающие данные не поставляются вместе с репозиторием кода; они получаются отдельно через ModelScope и локальный конвейер подготовки данных. См. ниже.

## Возможности

- **Вывод узкой IPA**: использует узкую схему UntPhesoca из [nk2028/putonghua-ipa-converter](https://github.com/nk2028/putonghua-ipa-converter), разметка на уровне фонем с сохранением тональных значений.
- **Полная тонкая настройка**: разморозка (unfreeze) кодировщика Conformer из SenseVoiceSmall и обучение вместе с новой IPA-головой; фронтенд признаков заморожен, `dither=0` гарантирует воспроизводимость.
- **Тональная метрика, не зависящая от метки**: точность тона вычисляется через таблицу сопоставления `ipa2tone` (IPA-слог → класс тона 1–5), независимо от конкретной фонемной записи, что упрощает честное сравнение.
- **Валидация в большом масштабе**: измерено на объединённом наборе валидации из 5918 примеров (см. [Метрики оценки](README.md#效果指标大规模验证)).
- **Демо Gradio**: поддерживает загрузку/запись аудио для распознавания и автоматическое сравнение различий с эталонным текстом (послоговое тональное выравнивание с подсветкой).

## Базовая модель

| Пункт | Описание |
| --- | --- |
| Название | SenseVoiceSmall (FunAudioLLM / Академия DAMO, Alibaba) |
| Источник | GitHub: [FunAudioLLM/SenseVoice](https://github.com/FunAudioLLM/SenseVoice); ModelScope: `iic/SenseVoiceSmall` |
| Структура | `WavFrontend` (признаки fbank + опц. f0) + кодировщик Conformer (512) + исходная CTC-голова иероглифов |
| Изменение в проекте | Фронтенд заморожен; поверх его кодировщика Conformer установлена новая **CTC-голова IPA** (см. ниже); исходная иероглифическая голова более не используется |

> Веса базовой модели автоматически загружаются и кэшируются ModelScope при первом запуске; ручная подготовка не требуется.

## Метод обучения

1. **Инициализация**: загрузка предобученных `WavFrontend` и `encoder` из SenseVoiceSmall (исходная CTC-голова иероглифов отбрасывается), затем создание новой CTC-головы IPA `ctc_head = Linear(512,512) → ReLU → Dropout(0.1) → Linear(512, vocab)`.
2. **Стратегия заморозки**: `WavFrontend` всегда заморожен, `dither` фиксирован на 0 (отключает случайный шум, гарантируя детерминированность признаков); кодировщик и IPA-голова **разморожены и полностью настраиваются** (поддерживается и обучение только головы).
3. **Потери и оптимизация**: `CTCLoss(blank=0)`; AdamW (`lr=1e-4`, `weight_decay=1e-4`); `CosineAnnealingLR` (`T_max = steps × epochs`); обрезка градиента 1.0.
4. **Точность**: смешанная точность bf16 (`autocast` применяется только к прямому проходу кодировщика; признаки и потери остаются fp32).
5. **Сохранение весов**: `best.pt` (минимальный TER валидации), `best_tone.pt` (максимальная точность тона).
6. **Совместимость со старыми весами**: при выводе/возобновлении обучения остаточные имена головы из старых весов автоматически переотображаются в `ctc_head.*`, чтобы избежать тихой потери головы.

## Быстрый старт

> Все скрипты разрешают `vocab/`, `data/`, `weights/`, `checkpoints/` и прочие относительные пути относительно «корня проекта» (т.е. корня репозитория), поэтому **не нужно `cd` в корень проекта, чтобы запускать из любого рабочего каталога**; абсолютный путь используется как есть.
> Базовая модель `iic/SenseVoiceSmall` — это model id ModelScope, при первом запуске автоматически загрузится и закэшируется.

> ### 【Важно】Сначала загрузите дообученные веса, иначе вывод — бессмысленный мусор
>
> Этот проект **не помещает веса модели в репозиторий** (опубликовано отдельно на ModelScope). Если вы запустите демо или вывод **без указания весов через `--ckpt`**,
> программа молча использует **случайно инициализированную** модель — IPA, которую она выдаёт для аудио, будет бессмысленной и часто с повторяющимися слогами,
> выглядит как «распозналось много», но это не настоящее произношение.
> Например, в первой половине *Цзинесы* (静夜思) всего ~10 слогов, но без весов может вывести 30+ повторяющихся мусорных слогов.
>
> Правильное использование (веса сначала нужно скачать в `weights/best.pt`, см. след. раздел):
> ```bash
> python app.py --ckpt weights/best.pt
> ```
> Если `--ckpt` не задан, `app.py` автоматически попытается найти `weights/best.pt`; если обоих нет, при запуске выводится заметное 【предупреждение】.

### 1. Получение весов модели

Веса модели **отсутствуют в этом репозитории**; загрузите их с ModelScope (опубликовано автором отдельно), напр.:

```bash
# Предполагая, что модель опубликована, используйте modelscope для локальной загрузки
modelscope download --model QiGuanFuChen/mandarin-ipa-asr --local_dir weights/
```

После получения `weights/best.pt` укажите его через `--ckpt`. (Если обучаете сами, дополнительно создастся `checkpoints/best_tone.pt`; см. «Руководство по обучению» ниже)

### 2. Вывод для одного аудио

```bash
# Не нужно cd в корень проекта: скрипт разрешает vocab/data относительно своей позиции; запускается из любого каталога
python src/infer.py --wav path/to/audio.wav --ckpt weights/best.pt
# Вывод: последовательность узких IPA-слогов через пробел
```

### 3. Пакетная оценка (метрики валидации)

```bash
python src/infer.py --eval --ckpt weights/best.pt \
    --val_scp data/val.scp --val_text data/val.text --limit 0
# Вывод TER / ACC / TACC / точность тона
```

### 4. Демо Gradio (загрузка аудио + авто-сравнение различий)

> Обязательно загрузите веса через `--ckpt` (см. 【Важно】 выше), иначе результат распознавания — бессмысленный мусор случайной инициализации.
> Вкладка «Распознавание» по умолчанию использует поиск луча (beam search, `--beam`, по умолчанию 12) для снижения ошибок вставки/повтора; `--beam 0` возвращает жадное декодирование.

```bash
# Запускается из любого каталога (относительные пути разрешаются относительно корня проекта); --ckpt принимает относительный или абсолютный путь
# Если --ckpt опущен, автоматически пробуется weights/best.pt
python app.py --ckpt weights/best.pt --port 7860
# Откройте http://127.0.0.1:7860 в браузере
```

- **Вкладка Распознавание**: загрузите или запишите аудио → выводит узкую IPA.
- **Вкладка Сравнение (авто-различие)**: загрузите аудио и (необязательно) введите эталонный IPA-текст →
  автоматически выполняется послоговое тональное выравнивание и подсвечиваются различия (верно / неверный тон / неверно прочитано / лишнее / пропущено);
  даже без эталона автоматически сравниваются два результата декодирования «жадное vs поиск луча».

## Руководство по обучению

1. Подготовьте данные (см. «Примечания к использованию данных» ниже), чтобы получить `train.scp` / `train.text` / `val.scp` / `val.text`
   (формат: `uid путь_к_аудио` и `uid IPA_слоги_через_пробел`).
2. Запустите:

```bash
python src/train.py \
    --train_scp data/train.scp --train_text data/train.text \
    --val_scp data/val.scp --val_text data/val.text \
    --vocab_path vocab/vocab_mandarin_ipa_combined.json \
    --ipa2tone_path vocab/vocab_mandarin_ipa_tone_combined.json \
    --output_dir checkpoints --epochs 10 --batch_size 16
```

Можно также записать параметры в `configs/example_train_config.json` и просто запустить:

```bash
python src/train.py $(python -c "import json,sys; c=json.load(open('configs/example_train_config.json')); print(' '.join(f'--{k} {v}' for k,v in c.items()))")
```

- Для warm-start из pinyin-весов полной настройки: `--warm_start weights/pinyin_ft.pt` (другая размерность головы автоматически пропускается и инициализируется случайно).
- Выводит `checkpoints/best.pt` (минимальный TER) и `checkpoints/best_tone.pt` (максимальный тон).

## Примечания к использованию данных (данные не публикуются)

По причинам лицензии и объёма **обучающие данные не публикуются напрямую**. Вы можете восстановить эквивалентный набор данных, выполнив шаги:

1. Скачайте корпус **zhvoice** (https://github.com/fighting41love/zhvoice), распакуйте для получения аудио и pinyin-текста.
2. Клонируйте **putonghua-ipa-converter** (https://github.com/nk2028/putonghua-ipa-converter), используйте его `data/putonghua.js` (scheme 2 = узкая UntPhesoca) для конвертации pinyin в узкую IPA.
3. Используйте `src/prepare_data.py` этого репозитория для генерации файлов, нужных для обучения:

```bash
# 1) подвыборка zhvoice -> текст узкой IPA + scp + словарь
#    --conv_js указывает на data/putonghua.js конвертера; --audio_root — корневой каталог аудио
python src/prepare_data.py build-zhvoice \
    --metadata zhvoice/metadata.csv \
    --audio_root zhvoice/wavs \
    --conv_js path/to/putonghua-ipa-converter/data/putonghua.js \
    --out data/zhvoice_ipa --train_n 8993 --val_n 918

# 2) конвертировать свой pinyin-текст с тонами в IPA (каталог должен содержать train/text, val/text)
python src/prepare_data.py build-mandarin \
    --text_dir data/mandarin_pinyin \
    --conv_js path/to/putonghua-ipa-converter/data/putonghua.js \
    --out data/zhvoice_ipa

# 3) слить несколько источников и расширить словарь, вывести файлы *_combined
python src/prepare_data.py combine \
    --zhvoice_dir data/zhvoice_ipa --mandarin_ipa_dir data/zhvoice_ipa \
    --out data/combined

# 4) расширить обучающий набор по коэффициенту (напр. 1,3×): база на мандаринской подвыборке, смешать данные zhvoice
python src/prepare_data.py scale \
    --mandarin_text data/combined/train_text --mandarin_scp data/combined/train_scp \
    --zhvoice_text data/zhvoice_ipa/train_text --zhvoice_scp data/zhvoice_ipa/train_scp \
    --factor 1.3 --out data/ipa130
```

Сгенерированные `*.scp` (пути к аудио) и `*.text` (метки IPA) можно использовать как вход для `train.py` / `infer.py`.
